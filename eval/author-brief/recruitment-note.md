# 人类轨招募材料（发给你要找的作者）

## 招募说明（邮件正文可直接用）

主题：邀请参与一项安全系统评估的独立攻击设计（约 2–4 小时，匿名）

我们在做一项安全运营（SOC）自动化系统的学术评估，需要几位未参与
系统构建的安全工程师，以独立作者身份设计攻击场景。你只会拿到一页
威胁模型简报（系统的管道描述 + 对手能力边界 + 五类危害定义），
看不到任何现有测试用例或防御实现——这正是独立性的意义。

**你要做的**：读简报（10 分钟），用提交表单写 2–3 个攻击叙事
（每个 15–40 分钟）。中英文均可。不需要跑任何代码。

**背景要求**：SOC/安全运营 或 K8s/云安全 方向的实际经验（两条线各
至少一人）。

** anonymization**：你在 artifact 与论文中以代号出现（如 author-H1），
真实身份只在最终定稿阶段由论文作者掌握，用于致谢（可选）。

**时间窗**：希望一周内回收。

附件：threat-model-brief.md + submission-template.md

## 给作者的答疑规则（招募方须知，不发给作者）

- 只能回答威胁模型层的问题（may/may-not 清单的含义、五类危害的
  边界、管道中某组件的职责）。
- 不得回答：现有用例长什么样、系统有哪些防御/检查、攻击"应该"
  往哪个方向提、任何关于评估结果的暗示。
- 答疑往来全量存档到 eval/author-brief/qa-log-H*.md（作者代号命名），
  作为盲化纪律的审计记录。
- 若作者主动问"你们是不是已经有 X 类用例"——回答："我们不能确认
  或否认任何已有用例的存在；请按简报本身工作。"

## 收回后的处置（招募方须知）

1. 每份提交原件存档：eval/author-brief/submissions/submission-H*-*.md，
   不做任何编辑。
2. 合式性过滤（仅语法性：叙事完整、落在威胁模型内、危害可猜），
   过滤数量与理由留痕；不合格的同样存档。
3. 翻译为可执行案例（作者叙事逐字保留在案例注释中），进入
   independent_cases.py，adversary="I"。
4. 旋钮外提案单列评估——如果成立，是我们系统的发现，不是作者的
   失误。
