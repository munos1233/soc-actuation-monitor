## 2. General Principles (non-negotiable across the whole plan)

1. **Freeze discipline**: once any layer is frozen, it is never silently re-run; new evidence always lands in a new layer, **never pooled**.
2. **Construct first, independent later**: all work that might change a gate (mutation testing, bug fixes) must be completed and frozen BEFORE independent authors enter. If a gate changes at all after authors write cases, the "frozen gates" claim is void.
3. **Handling a discovered harm** (at any stage): record it → decide whether it is a production bug or an instrumentation bug → fix the **production code** (not the cases) → re-freeze the affected layer → write it into the paper per the §eval-found pattern. Finding harm is an achievement, not an accident — R1's over-block is already the example.
4. **Page count**: `make paper-pages` gate at 35. Every evidence layer added must be offset by compression elsewhere.
5. **Citation discipline**: every agent-drafted citation (especially incident postmortems) must be human-verified item by item before entering the body.

## 5. Phase 2: Independent Case Authors (Weeks 3–5) [mixed; the key step is human]

> This is the main engineering body answering the "cases and gates share one author" objection (R2). **Start condition**: Phase 1 acceptance passed + gate-freeze declaration + protocol approved.

### 5.0 Decision point [human; decided before starting]

- **Dual track (recommended)**: human authors + blinded agent in parallel; the paper reports two lines, "human-authored (n) / agent-authored sessions (k)", and never merges them into one fabricated number;
- **Agent only**: evidence drops one tier; wording limited to "independent authoring sessions, blind to the case registry and gate internals".

### 5.1 Preparation [agent]

- Write a one-page threat-model brief + author submission template: it contains ONLY the threat model and harm definitions — no existing case list, no knob catalog, no gate implementation details (giving authors the knob catalog = the retag problem returns);
- Template fields: attack narrative (step by step) / which threat-model boundary it lands on / expected harm among five options (guessing allowed) / the step you guess is most likely to fail (guessing allowed) / references / why you think existing defenses might miss it.

### 5.2 Human track [human]

- Recruit 2–3 authors who did not participate in construction (at least one SOC-security background and at least one K8s-security background); send the brief; answer questions (only threat-model-level questions are allowed; no leaking the case space); collect the submission forms.

### 5.3 Blinded agent track [agent executes; human supervises discipline]

- Multi-family models (glm / deepseek / kimi / claude, reusing the planner-arm infrastructure) generate cases in **fresh sessions**: K sessions × M cases;
- The prompt contains only the brief; raw output is fully archived (including failed, duplicate, and naive ones).

### 5.4 Filtering and translation [mixed]

- Well-formedness filtering: syntactic only; filtering criteria and the counts at each tier are kept on record;
- Translate into `Injection`: create `backend/app/eval_suite/independent_cases.py` with `adversary="I"`; each case's comment records "author's original narrative → knob mapping";
- **Proposals outside the knob catalog are listed separately**: manual evaluation; if valid → a potential new harm class → extend the harness, then fix + disclose per §2.3 (this is not a nuisance; it is a selling point).

### 5.5 Execution and freezing [agent]

- **Whether or not harm is caught, report the whole thing faithfully**; zero breakthrough is the strongest independence evidence.

## 6. Phase 3: Multi-Person Co-Built Verification Layer — Tables and Gates (Weeks 4–5, may run parallel to Phase 2)

> "Multi-person co-built" is not just writing cases: let non-participants independently verify the existing tables and gates. This is the human version of artifact evaluation, the most direct answer to the "gates were reverse-engineered to fit the cases" objection.

### 6.1 Independent re-run of the tables [human + agent cooperating]

- One non-participant re-runs the main table on **their own machine** per REPRODUCE.md's three commands (`paper-eval-up / matrix / down`), and re-runs the kind table per `make paper-eval-k8s-kind` (needs local docker + kind);
- Diff every cell against the frozen `latest.json` / kind freeze; **record ALL discrepancies no matter how small** (first check environmental differences: PG version, timezone, mirror source);
- Add one line to the artifact and the body: "independent re-execution, date, environment, 0/N cell diffs".

### 6.2 Independent review of the gates [human]

- Another non-participant looks ONLY at the four mediator predicate sources + the paper's invariants, NOT at the case set, and answers item by item: "does the implementation == the semantics claimed in the paper": conforms / deviates + notes;
- The review record goes into the artifact; deviates are handled per §2.3;
- Cost ≈ one person, two days.

### 6.3 R3: Independent scoring of CVE mappings [mixed]

### 7.4b Three related-work items that MUST be added (conclusion of the 2026-09-16 audit of nearby prior work; missing any one is a reviewer hook) [agent drafts; human verifies]

1. **XACML/ABAC PIP (NIST SP 800-162) — highest priority.** SP 800-162 states verbatim: "attributes are stored in repositories and are retrieved through the Policy Information Point (PIP) at the time of an access request and prior to or during the computation of the decision" — the architecture concept of "fetching data from outside at decision time" has existed since 2003–2013. An access-control-savvy reviewer can say "this is just PIP". Related work must cite it and draw the delta clearly: ① the PIP fetches authorization attributes (who/what/env) and does **not constrain who writes those attributes**; ② it is not in the same transaction as the write (a cache is a vulnerability); ③ it does not answer "did the effect actually happen / can the record close up". TEI's three elements (non-proposer fact, in-write-transaction join, execution-side integrity) line up one by one.
2. **Gatekeeper data replication (sync → data.inventory) + CVE-2021-43979.** The attribute class itself has its own "attach state" answer (a replicated cache), and CVE-2021-43979 is exactly "processing requests before replication completes → policy bypass" — already in your corpus (`k_cve_2021_43979_no_reget`). Add one sentence in related work or §eval-k8s: "the attribute class can attach a cache; a cache is not a join inside the write (CVE-2021-43979)" — this elevates TEI's re-GET-in-review from "an implementation choice" to "a fix for a known flaw in the mainstream industry approach".
3. **The name "Evidence-based access control" is already taken** (Khantal/Helander/Zorn, W2SP 2008, Microsoft Research) — but its semantics are reputation/credential aggregation, with no conceptual conflict with TEI. Because this paper uses the word "evidence" heavily, add a footnote citing and distinguishing it, preempting "do you know this name was already used?".
